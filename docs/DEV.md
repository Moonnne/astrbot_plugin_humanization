# Humanization 开发说明

本文记录当前插件的代码结构、事件接入、数据协议和验证方法。安装、启用和配置说明见 [README](../README.md)，版本变化见 [CHANGELOG](../CHANGELOG.md)。

## 开发约定与目录

```text
main.py                     生命周期与 Handler 注册
metadata.yaml               插件元数据与版本
_conf_schema.json           官方配置控件、默认值及条件显示
core/
  astrbot_adapter.py        宿主接口、事件快照、历史过滤及模型调用
  runtime.py               记录、调度、规划、回复与重置的编排
  settings.py              配置校验、时段与提及策略
  management.py            管理员命令与重置确认
  recorder/                业务存取、日记协议与后台总结
  controller/              频率调度、规划协议、提示词与发送记录
models/                    消息、决策、时段、调度状态等数据模型
utils/                     扁平的运行时工具类
resource/
  prompts/                 固定模型协议
  sql/                     按用途分类的命名 SQL
test/                      隔离测试、替身及测试辅助代码
docs/DEV.md                随仓库维护的开发说明
```

- `main.py` 只处理宿主注册、参数转交和生命周期，业务进入 `core/`。
- 数据模型进入 `models/`；算法、配置校验和模型输出校验保留在对应业务模块。
- `utils/` 不嵌套目录，不放开发／测试工具，每个类处理明确的一类工作。
- 用户数据通过 `StarTools.get_data_dir()` 定位，不写入源码或 `resource/`。
- 注释、docstring 和日志事件使用英文，配置和面向用户的文档使用中文。复杂函数采用 Google 风格 docstring。
- 文本统一 UTF-8 无 BOM、CRLF；使用 `pathlib.Path`，不使用 PowerShell 修改文件。
- 不批量删除文件或目录；避免为未经要求的旧版本增加兼容分支或迁移代码。

运行依赖使用 AstrBot 已有的 `aiosqlite`、宿主接口和 Python 标准库，不新增安装项。测试使用 `pytest`、`pytest-asyncio`，检查使用 Ruff，不将开发依赖混入运行依赖。Windows 的时区数据由宿主已有依赖链提供。

## 宿主接入与事件流

支持 AstrBot `>=4.28.1,<5`、本地 Agent Runner、aiocqhttp / OneBot v11。最低版本来自所用原生请求收集接口的起始发布版本。

1. 宿主前置检查通过后，自定义过滤器选择目标会话；未唤醒主模型的普通消息也可进入观察。
2. Recorder 筛选、去重、入库。命令照常执行，是否过滤其记录与是否接管命令分开处理。
3. 对启用 Controller 的会话抑制默认 LLM，由插件选择何时提交原生请求。`should_call_llm(True)` 在当前宿主表示禁止默认调用，不是终止所有 Handler。
4. 群聊达到最低上下文要求后进入频率判断，随后调用 Controller 规划；私聊不检查该门槛。
5. 主模型使用原生 Agent、人格、工具与历史，完成工具循环和历史／统计收尾。
6. 本轮缓存的最终正文逐个 `yield`，继续经过原生装饰、发送及 `after_message_sent`。

自定义过滤器不绕过宿主白名单、会话处理开关、限流等前置检查。严格限流下，调度事件再次进入队列可能消耗一次检查机会。业务范围按平台实例、机器人身份和群／私聊区分，原 UMO 单独保留用于回复、权限与原生历史。

选中且启用 Controller 的会话先由 `prepare_input` 在 `maxsize` 优先级移除本事件待执行列表中的宿主 `handle_empty_mention`，避免该处理器以 `maxsize-1` 优先级先发起通用询问并进入等待。只修改本事件的处理器列表，不改全局注册表、配置或消息组件。原生群消息持久化及命令会话等待器保留；后续仍由普通观察、参与 Handler 处理。Controller 关闭时保留宿主空提及行为。空 @ 的原生请求用实际 `[@机器人ID]` 表示输入，保证原生构建器不会在插件注入前将其判为空请求。

选中会话的默认请求抑制与生成许可分开处理，许可被拒绝不能重新开放默认 @／唤醒回复。请求钩子还会按会话范围阻止观察期内非指令消息发起的未规划主模型请求，不依赖观察器已执行或已入库，并输出 `reply.blocked`；私聊跳过门槛，范围外会话及指令插件保留自己的请求流程。

最终正文不直接使用 `event.send()` 发送。工具调用中的文本、工具产物、媒体及宿主错误通知不统一套用角色正文协议。`ReplayResult` 继承原生结果类型，通过 `derive()` 保留发送阶段取出的语音等消息段，避免发送后记录遗漏媒体。

回合缓存只存在于内存，在完成、异常、取消或生成器关闭时释放；嵌套异步生成器使用确定性关闭。卸载／重载取消后台与回复任务、清理调度计时器，再关闭数据库和日志。

## 频率算法与并发调度

两种模式共用时区、分时段积极度、提及下限、冷却和合并设置。若未启用对应必回复，提及消息的有效积极度为：

```text
A_effective = max(当前时段积极度, 对应提及积极度下限)
```

同时命中 @ 与名称提及时采用 @ 分支。已开启的必回复绕过普通抽样、调度额度、冷却与退避，仍遵守群聊最低上下文及宿主权限，并调用 Controller 规划，要求 `reply=true`。

### 消息调度模式

每条成功入库的真人消息累加 `C += A_effective`，额度达到 1 时安排一次评估，保留小数部分，不堆积多个模型请求。使用 `Decimal` 避免 0.1 累加十次仍小于 1 的浮点误差。指令、去重消息和自身消息不贡献额度。

额度不足但有新消息时，使用有限等待补偿：

```text
W(A) = W_min + (W_max - W_min) × (1 - A)²
默认 W_min = 5 秒，W_max = 60 秒
```

积极度 0 不补偿；普通提及可加快到合并窗口。冷却、合并和退避使实际等待可能更长。连续第二次语义沉默起按 10、20、40、80、120 秒封顶退避，原生发送完成后清除。

每个群／私聊最多保留一个待评估快照和一个有效计时器。执行中的新消息留作下一批，观察使用提交时的序号截止点；同一批在回复、沉默、异常或宿主丢弃后消费一次机会，无新输入不重复请求。多个待处理必回复合并至最新的明确提及快照。

调度事件带专用标记，前置 Handler 阻止其重复执行其他消息插件及入站记录。事件保留输入、原 UMO 和本轮媒体资源，结束后释放；重置与重载使用代际和会话版本拒绝旧事件，不从历史数据库补发。

### 概率模式与主动发言

概率模式对候选消息判断 `R < A_effective`，随后进入语义规划。积极度控制评估频率，不是最终发言比例。

空闲主动检查仅针对整体启用的群。概率模式按“当前积极度 × 主动评估系数”抽样；调度模式累加该乘积，额度满 1 才规划。冷却、每日次数、免打扰与无人回应限制同时有效。新消息（含被过滤指令）会使旧空闲意图失效。主动事件使用群公共 UMO 和非管理员身份，不借用成员隔离历史或权限。

## 上下文与模型协议

### 输入与压缩

- Controller 和 Recorder 是独立的单次模型调用，不维护辅助聊天 session，也不自动使用原生 Agent 压缩。通过消息条数、完整话题选择和字符预算控制输入。
- 主模型保留原生历史与压缩，另外临时注入观察消息、日记和当前规划。临时内容不重复保存进原生历史。
- Controller 输入含固定协议、名称／别名、行为与场景片段、当前时间、触发信息、观察消息、话题及最近决策；不自动复制主人格、原生历史或工具列表。
- Controller 默认读取 30 条观察消息、跨日期的 30 个最近更新话题，话题共享 12000 字符预算。主模型和 Recorder 的常规日记选择最近两个有效日期，默认预算 2400 字符；省略完整条目并明确标记，不裁剪已存日记。
- 使用紧凑 JSON，避免把 JSON 资料再次转义为字符串。Recorder 将重叠消息放在新增消息之前，已有日记放在消息之后。缓存仍受窗口变化与提供商策略影响，不承诺固定命中率。

### 指令过滤

`filter_commands` 统一控制插件入库和接管的 LLM 输入。识别注册指令与配置前缀，阻止未注册前缀指令回落到默认 LLM；原始入库过滤与后续观察筛选同时生效，不重写已有日记。

原生 Agent 开始前临时取出可按前缀识别的指令回合，连同其回复和工具消息；结束钩子恢复后再由宿主保存，保留原生指令记录。引用中的指令内容同样过滤。压缩后的普通内容不复原，恢复时依据仍保留的消息定位；结束、异常、取消时释放临时引用。没有前缀的旧指令无法可靠识别。原生完整群消息库及其历史查询工具不在该过滤范围内。

### Recorder 日记协议

固定系统协议位于 `resource/prompts/summary.txt`，解析与验证在 `core/recorder/diary.py`。

- 仅接受 `{"changes":[...]}`。`add` 提交完整主题、用户行为、我的行为与反应；`update` 按当前可见的当日话题 ID 局部修改。
- 每项变更必须引用本轮提供的 `evidence_seqs`，且至少包含一条未总结的新消息；同一条目一次不能重复更新。
- 程序写入会话、日期、时间及序号范围，模型不能指定存储目标。新增话题时间取证据中最早消息序号对应的发送时间；更新保留原时间，并扩展来源范围。
- 空变更正常推进游标；非法输出或数据库失败整批回滚。输出超过默认 6000 字符时不裁切、不推进，等待后续重试。
- 当日允许更正，历史日记封存。跨日积压在整理当天补记，历史错误在当天更正，实际话题时间保留原日期。
- 原始消息滚动缺失或输入截断写入覆盖缺口；预算省略另行标记，不宣称日记完整。

程序按日期标题与 `[Time]`、`[Topic]`、`[Interact]`、`[Reply]`、`[Reaction]` 渲染阅读文本，数据库不重复存整篇正文。字段分类不代表实际行为的先后顺序。

### Controller 规划协议

固定协议位于 `resource/prompts/gate.txt`，校验在 `core/controller/protocol.py`。顶层严格为 `reply`、`reason`、`emotion`、`plan`：

```json
{"reply":false,"reason":"话题与我无关。","emotion":{"primary":"NEUTRAL","intensity":0},"plan":null}
```

回复计划严格包含 `participation`、`target_message_id`、`topic_id`、`intent`、`style`、`guidance`。参与方式为回应、加入、主导或开题；焦点必须来自本轮可见消息／话题，语义焦点不自动改变路由或调用引用接口。

14 个主情绪为项目自定义分类；`NEUTRAL` 强度为 0，其余为 1—3。交互意图、表达风格与情绪分别校验。reason 最多 80 字符，guidance 最多 300 字符，完整 JSON 最多 4096 字符；这些是接收校验限制，不是服务商生成 Token 限制。拒绝围栏、额外字段、非法类型、枚举和不可见 ID，不修补或截断。

普通规划失败保持安静。必回复仍调用规划且要求回复，未配置或失败时保留主模型入口，不伪造情绪或有效规划记录。

每个会话在 SQLite 保留最近 10 条有效决策，包括沉默；重启延续，重置时清除。后续输入仅投影旧情绪、结论、时间、焦点和执行状态，不重复旧 guidance。模型根据实际间隔与新刺激延续或减弱情绪，无独立轮询或固定衰减公式。

规划执行状态包括 `observed`、`pending`、`processed`、`unconfirmed`、`failed`、`superseded`。重启将遗留 pending 标为 unconfirmed。`processed` 仅代表原生发送阶段完成，不等于平台送达或对方已读。

### 主模型与最终输出

主模型收到本轮情绪、计划和必要焦点快照，不接收全部决策历史。表达与场景片段在配置中编辑或选择人格正文覆盖；固定正文协议位于 `resource/prompts/output.txt`。

最终正文为单行，以半角 `$` 分隔 1—3 个气泡。文字末尾允许一个 emoji（可含肤色、连接符或国旗组合），不允许在句中、前面的气泡或独立气泡中使用；先规范末尾句号，再保留 emoji。少量使用由提示词引导，不新增跨轮计数或概率抽样。非流式校验失败最多修复一次，再失败仅过滤正文、保留媒体并允许 Agent 收尾。修复不用于 Controller 或 Recorder JSON。语义约束仍依赖模型，解析器不能精确识别所有舞台描写。

## 数据库与事务

数据库路径为插件数据目录下的 `chat/db/chat.sqlite3`，全部业务共用该文件。

| 固定表 | 用途 |
| --- | --- |
| `sessions` | 会话路由、序号、摘要进度、活动与主动发言状态 |
| `messages` | 有界原始聊天及已记录的机器人气泡 |
| `diary_days` | 会话每日索引、覆盖状态及封存状态 |
| `diary_topics` | 独立话题内容、来源与更新时间 |
| `reply_runs` | 回复执行记录，全库保留最近 1000 条 |
| `controller_decisions` | 每会话最近 10 条有效规划及执行状态 |

消息以会话、方向和非空消息 ID 去重，按每会话保留条数滚动。媒体只存类型标签，不存资源地址或二进制。最低上下文直接查询当前保留行数；摘要触发使用新增入站消息计数，与保留行数含义不同。

`diary_topics` 通过复合外键关联每日索引，删除日期级联删除话题。每日索引可在 `today` 重置后独立于 `sessions` 保留，保证历史日记仍可读取。

### 存取接口

- `core/recorder/storage.py` 组合业务查询与事务，调用者不管理连接、锁或 SQL。
- `utils/database.py` 统一持有一个串行写连接与两个可复用的只读连接。读快照隔离未提交写入；写事务采用 `BEGIN IMMEDIATE`。
- `utils/database_session.py` 提供查询与执行，返回已取出的数据或不持有游标的 `WriteResult`。取消时先等待已排队 SQLite 操作结束并关闭游标，再传播取消。
- `utils/sql_queries.py` 从 `resource/sql/` 读取 `-- name: 名称` 语句，按 `文件名.名称` 查找；参数通过 SQLite 绑定传入，不拼接用户文本。

建表在 `schema.sql`，连接参数与 checkpoint 在 `connection.sql`，其他语句按表／用途分类。禁止将运行 SQL 重新内嵌进 Python 方法；测试可使用 SQL 建立隔离场景或注入失败。

去重、入库、计数和裁剪是一笔事务；话题变更、每日索引和摘要游标同样原子提交。失败或提交前取消回滚。多查询信息页和日记视图使用同一读快照。事务内不等待模型或网络，避免长期持有锁及 WAL 快照。

### WAL 与关闭

采用 WAL 模式，保留 1000 页自动 checkpoint，`busy_timeout=5000`，`journal_size_limit=4194304`。后者只限制 WAL 重置后保留的空间，不是增长硬上限。

关闭时拒绝新操作，等待已受理操作完成，关闭读连接，再执行 `wal_checkpoint(TRUNCATE)` 并关闭写连接。记录 `database.checkpoint` 的 `busy`、`log`、`checkpointed`；失败记录异常并释放连接。取消关闭调用也会等待内部清理任务完成。

`-wal` 是日志文件，`-shm` 是共享索引，不能手动删除。正常最后连接关闭会整理辅助文件；其他程序的长读事务可能阻挡 checkpoint，异常退出也可能留下文件。该流程不执行 `VACUUM`，删除行不保证主文件立即缩小。机制参见 [SQLite WAL](https://www.sqlite.org/wal.html) 和 [checkpoint](https://www.sqlite.org/pragma.html#pragma_wal_checkpoint)。

当前迭代按新的话题表结构实现，不提供旧测试数据迁移。升级旧测试实例前停止插件，自行备份或丢弃旧测试数据；程序不自动清空数据库。请勿在测试中访问真实数据路径。

## 管理与重置

管理过滤器同时检查功能开关和 AstrBot 管理员权限，非管理员静默。命令回复继续走原生发送流程。日志清空在写入队列中执行，等待较早记录完成，后续日志正常写入。

重置请求按发起会话、管理员身份与 60 秒期限匹配；指定目标 UMO 只允许私聊发起，确认仍在发起会话完成。无效目标不创建请求，并取消本人该发起会话中的旧请求。跨午夜确认使用请求时明确的日期。

单会话重置取消旧回复、摘要、调度并清理进度与决策。`all` 删除该会话全部日记；`today` 删除全部原始聊天和回复／决策记录，只删请求当天日记。群聊按整群执行，已知成员隔离路由也切换至空白原生对话，保留旧对话及人格选择。

面板全量清理在保存重载时消费一次，先保存撤销操作开关与确认文字，再执行清理，避免反复加载时重做。覆盖当前停用及只保留历史日记的会话。SQLite 删除与 AstrBot 原生会话切换属于不同存储，不提供跨库原子性，出错时如实报告部分完成情况。

## 日志与调用统计

控制台使用 AstrBot 插件 logger，文件通过 `PluginLog` 异步队列写入，不替换全局 Handler。每条记录为 UTF-8／CRLF JSON，正文换行和异常堆栈转义在字段中。

| 模式 | 控制台 | runtime.log | dev.log |
| --- | --- | --- | --- |
| 普通 | 核心动作与异常类型，模型用量不回显 | 核心日志和模型用量 | 不新增 |
| 调试 | 本插件不输出 | 模型用量摘要 | 核心、用量及完整调试详情 |

文件默认上限 5／10 MB，0 无限制，按实际 UTF-8 字节数保留最新完整 JSON 行。单条记录超过上限时跳过，不截断 JSON 或中文；加载时也裁剪已有超限文件。关闭等待队列完成，写盘失败仅向宿主报告一次错误类型。

- `summary.complete`：会话、实际新整理条数、包含重叠的输入条数、耗时、新增／更新话题数；仅在提交成功后输出。
- `summary.failed`：会话、耗时、错误类型、成功提交条数 0、候选条数；候选数不当作实际输入数。
- `gate.complete`：会话、reply／wait、主情绪及强度、参与方式、耗时。reason、guidance 与正文仅在调试日志记录。
- `model.usage`：Controller、Recorder、格式修复每次调用及原生主模型可观察步骤的用量。普通与调试模式均写入 runtime.log，调试模式同时写 dev.log，不打印控制台。

用量字段含 `estimated_input`、`usage.input`、`usage.input_cached`、`usage.output`、`usage.total`、`cache_ratio`、提供商／响应 ID、状态和辅助调用耗时。估计采用宿主启发式，不含工具 schema，不作计费依据。提供商原始详情只取已知数值字段，缓存字段优先级和来源显式记录；缺失为 null，不能将未报告缓存理解为没有缓存。

主模型通过原生 Runner 和工具钩子记录 `scope=native_step` 增量，同一次模型请求的多个工具不重复计数；辅助模型为 `scope=call`。宿主内部重试、工具参数补全及压缩模型不具备相同逐次统计，不宣称全部覆盖。接入代码集中在宿主适配模块，只读访问原生 Runner 信息。

普通日志不记录聊天正文、日记、完整提示词或凭据；调试日志记录详细资料但脱敏已知凭据并省略二进制，分享前仍须检查。运行数据库、日志与密钥不提交 Git。
