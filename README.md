# Humanization

<img src="logo.png" alt="Humanization" width="128" />

让 AstrBot 先听懂聊天，再决定是否加入。Humanization 提供聊天记录、话题日记、回复调度与情绪规划，让机器人根据语境、兴趣和角色风格参与群聊或私聊。

**版本：v0.1.3** · **作者：Moonne** · [项目仓库](https://github.com/Moonnne/astrbot_plugin_humanization) · [更新日志](CHANGELOG.md)

## 功能介绍

- **Recorder 聊天感知**：记录普通聊天，后台整理话题日记，保留参与者行为、机器人回应与用户反应。
- **Controller 行为规划**：综合近期消息、历史话题和情绪，决定是否回复，并指导主模型表达。
- **两种回复模式**：默认消息调度模式，也可选择概率抽样；支持群聊／私聊分时段积极度、名称和别名识别。
- **先观察再参与**：群聊默认积累 50 条有效记录后才允许回复；私聊不受此门槛限制。
- **空闲主动发言**：可选在群聊长时间无人发言时主动开话题。
- **管理与排查**：管理员查询／重置会话，日志记录整理结果、回复规划及模型 Token／缓存数据。

主模型继续使用 AstrBot 的人格、工具和原生 Agent 流程，支持工具循环、历史保存、统计、TTS、文转图、自动引用和原生分段。插件不增加额外运行依赖。

## 运行要求

- AstrBot `>=4.28.1,<5`，使用本地 Agent Runner。
- aiocqhttp / OneBot v11 适配器，例如 NapCat、SnowLuma。
- AstrBot 中已配置可用的主回复模型；摘要和行为规划模型在插件中分别选择。

群聊按整个群记录与规划，私聊独立处理。普通消息即使没有唤醒主模型，也可以被记录；宿主白名单、限流等前置检查仍然有效。

## 快速开始

1. 在 AstrBot 插件管理中，通过仓库地址安装本插件。
2. 打开插件配置，在“会话启用范围”选择会话，或填写补充 UMO。默认范围为空，尚未接管任何会话。
3. 在 Recorder 开关下选择**摘要模型**，在 Controller 开关下选择**聊天行为规划模型**。主回复模型沿用 AstrBot 当前会话配置。
4. 填写机器人名称和别名，并在 AstrBot 主人格中同步说明这些称呼。
5. 保持默认“消息调度模式”，按需要调整群聊／私聊积极度和行为、表达提示词，保存配置。
6. 群聊先积累默认 50 条有效记录，再开始正常评估；达到门槛不代表立即发言。需要首次联调时可临时降低门槛。

未选摘要模型时只记录原始聊天。未选规划模型时普通消息保持安静；开启的必回复仍可提交主模型，但群聊必须先满足最低上下文要求。

## 配置说明

### 会话范围与模块开关

通过 `/sid` 获取实际 UMO。格式中的方括号表示占位符，填写时替换为实际值，不输入方括号：

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 群聊 | `[平台实例]:GroupMessage:[群号]` | `onebot:GroupMessage:123456` |
| 私聊 | `[平台实例]:FriendMessage:[用户号]` | `onebot:FriendMessage:123456` |

“平台实例”是你在 AstrBot 中配置的实例 ID。即使开启了群成员会话隔离，选择整个群仍使用群号格式。已知会话列表在启动／重载时刷新，未显示的会话可手动补充。开启“全部会话”后，两项范围输入隐藏。

| 设置 | 生效行为 |
| --- | --- |
| Recorder 与 Controller 均开启 | 在选中会话记录、整理并控制主模型回复 |
| 关闭 Controller | Recorder 继续记录和整理，回复恢复 AstrBot 原规则 |
| 关闭 Recorder | 停止记录、整理和 Controller 接管，回复恢复 AstrBot 原规则 |
| 宿主自定义规则关闭“启用 LLM” | 停止 Controller 规划和主模型回复，Recorder 仍可记录、调用摘要模型 |
| 宿主关闭该会话“消息处理” | 消息无法进入插件，Recorder 也不能继续记录 |

### Recorder：记录与日记

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 过滤指令模式对话 | 开启 | 指令不进入插件记录及接管的 LLM 输入；原生指令记录保留 |
| 额外指令前缀 | `/` | 补充识别未注册指令，可填多个，不要填普通昵称 |
| 每个会话保留消息条数 | 500 | 保留最近记录，包含已记录的机器人气泡 |
| 群聊最低上下文 | 开启，50 条 | 只统计当前实际保留记录，门槛须为 1 至保留上限，私聊不限制 |
| 新增用户消息后触发摘要 | 100 条 | 只按新入站消息计算，机器人气泡不增加此计数 |
| 单次摘要最多读取消息条数 | 200 | 必须满足“触发条数 ≤ 摘要窗口 ≤ 保留条数” |
| 消息正文上下文字符预算 | 16000 | 限制观察资料的大小 |
| 日记上下文字符预算 | 2400 | Recorder 与主模型读取近期日记时使用，选择完整话题 |
| 单次日记变更输出字符上限 | 6000 | 限制一次总结输出，不限制每日累计日记 |
| 摘要模型超时 | 60 秒 | 超时或输出错误时保留进度，后台后续重试 |

日记按会话、日期和话题保存，允许补充或更正当天话题，历史日期封存。聊天记录滚动删除，日记持续保留至管理员清理。图片／视频／文件在插件记录中使用 `[image]`、`[video]`、`[file]` 等标签；媒体理解由宿主处理。

最低上下文沿用 Recorder 的指令过滤和去重，滚动删除的消息不计数。观察期间仍记录、整理日记，群聊中的 @／提及必回复和主动发言也受门槛限制；重置群聊数据后重新积累。

### Controller：频率与回复规划

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 工作模式 | 消息调度 | 累加积极度安排评估；可切换概率抽样 |
| 机器人名称／别名 | `Bot`／空 | 用于点名识别和 Controller 身份提示，需另行同步到主人格 |
| 群聊／私聊积极度 | 0.2／0.8 | 控制评估频率，范围 0—1 |
| @ 必回复／提及必回复 | 开启／关闭 | 绕过普通频率门控和冷却，仍规划情绪与表达 |
| 名称提及／@ 积极度下限 | 0.3／1.0 | 未启用对应必回复时，提高该消息的评估频率 |
| 时区 | `Asia/Shanghai` | 用于时段、日记和日志时间 |
| 普通回复冷却／合并等待 | 20 秒／1.5 秒 | 控制连续发言并合并相邻消息 |
| 调度最短／最长补偿等待 | 5 秒／60 秒 | 低流量时也提供评估机会，仅调度模式显示 |
| Controller 和主模型观察消息条数 | 30 | 与群聊最低上下文门槛独立 |
| Controller 读取话题数／字符预算 | 30／12000 | 跨日期选择最近更新的话题，条数为 0 时不读取 |
| 门控／格式修复超时 | 30 秒 | 普通规划失败保持安静，必回复保留主模型入口 |
| 代理回合禁用工具 | 空 | 从宿主允许的工具中进一步移除指定工具 |

积极度是**评估机会的频率**，实际发言还由 Controller 判断。调度模式下，0.1 名义上约每 10 条消息评估一次，0.2 约每 5 条，0.5 约每 2 条，0.8 平均约每 1.25 条；低流量补偿、合并、冷却与退避会改变实际间隔。概率模式按积极度随机抽样。

积极度为 1 仍允许 Controller 决定沉默；为 0 时普通消息不评估，已开启的必回复仍有效。必回复只要求进入回复流程，角色仍可拒绝用户任务。

可配置多个群聊／私聊积极度时段，未覆盖时使用默认值。支持跨午夜；开始时间包含、结束时间不包含，相同起止表示全天，时段不能重叠。配置页只显示当前模式的专属参数；频率估计在保存重载并重新打开页面后更新。

Controller 会规划当前情绪、参与方式和回复方向，每个会话保留最近 10 条有效决策，供后续判断参考。名称和别名识别只是线索，模型仍会结合语境判断消息是否指向自己。

### 空闲主动发言

默认关闭，仅用于已整体启用的群聊。默认无人发言 60 分钟后，每 15 分钟检查一次；距机器人上次发言至少 240 分钟，每群每天最多 2 次。主动评估系数默认 0.5，23:00—08:00 默认免打扰。

主动发言仍需 Controller 判断；开启不代表必定开口。无人回应后不连续追发，新消息会使过时的主动意图失效。

### 提示词与人格

主回复人格使用 AstrBot 当前人格。插件另外提供“行为风格”“表达风格”“群聊”“私聊”四份可编辑文本，也可选择人格正文覆盖：

- 行为风格指导 Controller 是否参与及如何规划。
- 表达风格指导主模型如何说话。
- 群聊／私聊文本按场景提供给 Controller 和主模型。

Controller 不会自动读取主人格，角色的重要兴趣、边界和倾向也应写入行为风格。选择人格覆盖后，以该人格正文为准；文本留空并保存重载会恢复默认值。

最终聊天正文采用单行纯文本，可用半角 `$` 分成 1—3 个气泡。格式错误时最多修复一次。固定 JSON 与输出协议由插件维护，风格文本应与其一致。

### 日志设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 调试模式 | 关闭 | 普通模式输出核心日志；调试模式将详情写入文件 |
| `runtime.log` 大小上限 | 5 MB | 核心日志与模型用量摘要 |
| `dev.log` 大小上限 | 10 MB | 调试模式下的详细日志 |

容量按 1 MB = 1024 × 1024 字节计算，可填非负小数，0 表示无限制。两份日志按容量保留最新完整记录，保存重载后生效。

普通模式在 AstrBot 控制台显示核心操作与错误；调试模式下本插件日志不输出到控制台。主模型、Recorder、Controller 和格式修复可观察到的 Token／缓存统计都会写入 `runtime.log`，不回显控制台；提供商未报告的数据会标为缺失。

## 管理指令

在设置中开启“管理指令”（默认关闭），并将宿主唤醒前缀配置为包含 `/`。若同时使用空前缀，将 `/` 排在空前缀之前。配置 `/` 后仍能监听普通聊天。

所有 `/hum` 指令仅 AstrBot 管理员可用，普通用户使用时不回应。`[UMO]` 是可选参数，省略表示当前会话，指定目标的重置命令只允许在管理员私聊中使用。

| 指令 | 位置 | 功能 |
| --- | --- | --- |
| `/hum info [UMO]` | 群聊／私聊 | 查询会话名称、UMO、记录条数、日记版本与进度、辅助模型及查询时间 |
| `/hum clear log` | 私聊 | 清空 `runtime.log`，回复 `done` 或错误 |
| `/hum clear dev_log` | 私聊 | 清空 `dev.log`，也接受 `/hum claer dev_log` |
| `/hum reset_data all [UMO]` | 当前会话，或私聊指定目标 | 清空全部聊天、日记、规划记录与进度，主模型切换空白对话 |
| `/hum reset_data today [UMO]` | 同上 | 清空全部聊天和规划记录，只删请求当天日记，保留此前日记 |

重置需同一管理员在发起请求的同一会话内，于 60 秒内输入 `/hum IClearKnowWhatIDoingNow` 确认，超时不执行。群聊重置作用于整群，主模型旧对话保留供查看；此前日记在 `today` 重置后仍可被读取。

例如，在管理员私聊中发送 `/hum reset_data all onebot:GroupMessage:123456`，再在该私聊确认，即重置目标群。

设置页最下方的“危险操作区”可清除所有已记录会话的数据。开启操作开关，完整输入 `CLEAR_ALL_HUMANIZATION_DATA` 并保存后执行一次；同时为对应主模型新建空白对话，保留原生旧对话和日志文件。

## 数据与常见问题

数据保存在 AstrBot 插件数据目录：数据库为 `chat/db/chat.sqlite3`，日志为 `log/runtime.log` 和 `log/dev.log`。日志与数据库不要提交 Git；调试日志包含聊天与模型内容，分享前先检查。

- **没有回复？** 检查会话范围、模块开关、宿主 LLM 开关、规划模型及群聊最低上下文，再看 AstrBot 的规划日志。评估通过也可能决定沉默。
- **没有日记？** 需要选择摘要模型并积累足够新增用户消息，整理在后台进行，不阻断聊天回复。
- **指令为什么还在原生记录中？** 过滤控制插件记录和 LLM 输入，原生记录保留；已有日记不会因修改过滤设置而重写。
- **数据库旁有 WAL／SHM？** 它们由 SQLite 管理，正常运行时存在是正常现象；插件关闭时会尝试整理，外部读连接可能阻止完成，不要直接删除。
- **配置了名称，主模型仍不认识外号？** 名称／别名只自动注入 Controller，需要同步到 AstrBot 主人格。

开发结构、协议、算法、数据库及验证方式见 [开发说明](docs/DEV.md)；各版本变化见 [CHANGELOG](CHANGELOG.md)。
