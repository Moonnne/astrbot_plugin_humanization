# Humanization

<img src="logo.png" alt="Humanization" width="128" />

让 AstrBot 先听懂聊天，再决定是否加入。Humanization 提供聊天记录、话题日记、回复调度与情绪规划，让机器人根据语境、兴趣和角色风格参与群聊或私聊。

**版本：v0.1.5** · **作者：Moonne** · [项目仓库](https://github.com/Moonnne/astrbot_plugin_humanization) · [更新日志](CHANGELOG.md)

## 功能介绍

- **Recorder 聊天感知**：记录普通聊天，后台整理话题日记，保留参与者行为、机器人回应与用户反应。
- **Controller 行为规划**：综合近期消息、历史话题和情绪，决定是否回复，并指导主模型表达。
- **两种回复模式**：默认消息调度模式，也可选择概率抽样；支持群聊／私聊分时段积极度、名称和别名识别。
- **先观察再参与**：群聊默认积累 50 条有效记录后才允许回复；私聊不受此门槛限制。
- **空闲主动发言**：可选在群聊长时间无人发言时主动开话题。
- **管理与排查**：管理员查询／重置会话，日志记录整理结果、回复规划及模型 Token／缓存数据。
- **可视化管理**：在 AstrBot 面板内查看统计、聊天、最近反应、话题与日记，筛选和批量删除记录，编辑插件设置。

主模型继续使用 AstrBot 的人格、工具和原生 Agent 流程，支持工具循环、历史保存、统计、TTS、文转图、自动引用和原生分段。插件不增加额外运行依赖。

## 运行要求

- AstrBot `>=4.28.1,<5`，使用本地 Agent Runner。
- aiocqhttp / OneBot v11 适配器，例如 NapCat、SnowLuma。
- AstrBot 中已配置可用的主回复模型；摘要和行为规划模型在插件中分别选择。

群聊按整个群记录与规划，私聊独立处理。普通消息即使没有唤醒主模型，也可以被记录；宿主白名单、限流等前置检查仍然有效。

## 快速开始

1. 在 AstrBot 插件管理中，通过仓库地址安装本插件。
2. 打开插件配置中的“会话启用范围”，开启“监听会话”，选择白名单或黑名单模式。默认白名单为空、范围外“旁观”：记录聊天，并在配置摘要模型后整理话题、日记，不回复。将需要正常回复的会话加入白名单，处理方式保留“正常”。
3. 在 Recorder 开关下选择**摘要模型**，在 Controller 开关下选择**聊天行为规划模型**。主回复模型沿用 AstrBot 当前会话配置。
4. 填写机器人名称和别名，并在 AstrBot 主人格中同步说明这些称呼。
5. 保持默认“消息调度模式”，按需要调整群聊／私聊积极度和行为、表达提示词，保存配置。
6. 群聊先积累默认 50 条有效记录，再开始正常评估；达到门槛不代表立即发言。需要首次联调时可临时降低门槛。

未选摘要模型时只记录原始聊天。未选规划模型时普通消息保持安静；开启的必回复仍可提交主模型，但群聊必须先满足最低上下文要求。

## 可视化管理页面

安装或重载插件后，在 AstrBot 左侧“扩展功能”中打开 **Humanization**，也可从插件详情页进入视图。页面包含统计、聊天、最近反应、话题、日记、提示词、设置七个标签，“设置”位于最右侧，跟随宿主切换明暗主题。

- 数据页左侧筛选栏默认展开，可折叠。支持搜索并多选已启用的会话，筛选群聊／私聊、日期、关键词和排序；点“查看详情”可展开结构化 JSON。
- 表格直接显示群名／私聊会话名；悬停时显示平台、类型和 UMO。群名复用 AstrBot 名称，并通过 OneBot 群列表补充，缓存 10 分钟；接口失败时保留已知名称或群号。长内容以省略号显示，悬停查看全文；操作列固定在右侧。点击数据列表头可切换升降序，分隔线支持拖动调宽和双击恢复默认宽度。
- 聊天可按收发方向、发送者、消息内容类型筛选；最近反应可按回复决定、执行状态、情绪、触发来源和必回复筛选；话题可按参与行为及我的行为关键词筛选；日记可按封存状态和覆盖缺口筛选。
- 支持单条删除和当前页多选删除，执行前显示确认。删除日记会同时删除该日期的话题；删除聊天记录不会改写已有日记，也不会回退累计消息序号，但会影响群聊最低上下文的实际条数。
- 统计展示插件数据库目前保留的数据；近期决策每个会话最多 10 条，“决定回复”不等于实际发送次数。
- 设置与原生插件配置共用同一份文件。修改后显示未保存提醒，切换内部标签时可选择保存并切换、放弃并切换，或关闭弹窗继续编辑。保存时校验并重载 Humanization，进行中的回复可能中断；保存失败会留在设置页。
- 设置左侧提供可折叠的快速导航，沿用 AstrBot 侧栏的图标和选中高亮，高亮随页面滚动更新；右侧固定单列，卡片两侧留白并限制最大宽度。最下方红色危险操作区通过按钮和输入确认立即清除数据，与配置保存独立。
- “提示词”使用对齐的网格卡片，独立编辑行为、表达、群聊和私聊四层片段，支持人格选择及字数／Tokens 估计。点击“对比默认”，左栏编辑自定义文本，右栏查看只读默认文本，两栏下方均显示统计；窗口右上“显示差异”可切换为按行对齐的差异视图。未自定义时直接显示默认正文，仅浏览不写回配置；未选择人格且文本留空时自动使用默认 TXT，点击“使用默认”后保存即可恢复。

页面操作要求登录 AstrBot 面板。删除只作用于 Humanization 数据；处理中的会话会暂时拒绝删除，可在回复／整理结束后重试。发布包包含构建好的页面，使用时不需要安装 Node.js。

## 配置说明

### 会话范围与模块开关

通过 `/sid` 获取实际 UMO。格式中的方括号表示占位符，填写时替换为实际值，不输入方括号：

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 群聊 | `[平台实例]:GroupMessage:[群号]` | `onebot:GroupMessage:123456` |
| 私聊 | `[平台实例]:FriendMessage:[用户号]` | `onebot:FriendMessage:123456` |

“平台实例”是你在 AstrBot 中配置的实例 ID。即使开启了群成员会话隔离，选择整个群仍使用群号格式。已知会话列表在启动／重载时刷新，未显示的会话可手动补充。

“监听会话”是总开关，关闭后插件不处理普通消息，交由 AstrBot。下方“工作模式”使用互斥按钮：**白名单模式**中，名单内默认正常工作，名单外默认旁观；**黑名单模式**中，名单外正常工作，名单内默认旁观。可更改默认方式，也可在会话列表中逐项覆盖为以下五种方式。两种名单及其独立规则分别保存，切换不会丢失选择。

点击“选择或添加会话”，可按名称、ID、UMO 搜索已有会话，筛选群聊／私聊并多选添加，也可补充未知会话的 UMO。列表展示名称、实际适配器类型、支持状态和会话 ID；图标使用宿主注册资源，无可用图标时显示通用图标，未知适配器不会标成 OneBot。其他平台会话可查看，但当前消息处理仍仅支持 OneBot。保存前校验 UMO 格式，自动去除首尾空白。旧版“全部会话”开关对应新版黑／白名单模式，已有名单和策略保留，不会自动重置为新默认值。

| 处理方式 | 普通消息的行为 |
| --- | --- |
| 正常（白名单内默认） | 按 Recorder／Controller 配置记录、整理话题日记并进入回复流程 |
| 跳过 | 跳过 Humanization，由 AstrBot 按原配置处理 |
| 监听 | 只按 Recorder 过滤规则入库，不整理日记、不调用 Controller／主模型、不主动发言；普通插件指令正常执行 |
| 旁观（新配置的范围外／黑名单内默认） | 记录聊天，允许 Recorder 模型整理话题和日记，不调用 Controller／主回复，不主动发言 |
| 丢弃 | 不入插件库，阻断普通消息的后续 AstrBot 处理 |

**已匹配的插件指令始终豁免范围策略，包含“丢弃”；指令自行发起的 LLM 请求也不受本插件门控。** `/hum` 同样豁免会话范围，但仍需开启“管理指令”并具有 AstrBot 管理员权限。仅有 `/` 等前缀但未匹配插件指令的消息不享受该豁免。范围策略在 Recorder 开启时生效；监听期间的数据保留，之后恢复正常或旁观时可以用于日记整理。旁观仍需配置 Recorder 摘要模型，并达到摘要触发条件；不会生成 Controller 的“最近反应”记录。

| 设置 | 生效行为 |
| --- | --- |
| Recorder 与 Controller 均开启 | 在选中会话记录、整理并控制主模型回复 |
| 关闭 Controller | 正常启用会话的 Recorder 继续记录和整理、回复恢复 AstrBot 原规则；监听／旁观／丢弃策略仍然生效 |
| 关闭 Recorder | 停止范围策略、记录、整理和 Controller 接管，回复恢复 AstrBot 原规则 |
| 宿主自定义规则关闭“启用 LLM” | 停止 Controller 规划和主模型回复，Recorder 仍可记录、调用摘要模型 |
| 宿主关闭该会话“消息处理” | 消息无法进入插件，Recorder 也不能继续记录 |

### Recorder：记录与日记

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 过滤指令模式对话 | 开启 | 指令不进入插件记录及接管的 LLM 输入；原生指令记录保留 |
| 额外指令前缀 | `/` | 补充识别未注册指令，可填多个，不要填普通昵称 |
| 过滤群机器人消息 | 开启 | 使用 SnowLuma 的 `is_robot` 标识过滤入库及模型输入，身份未知时保留 |
| 每个会话保留消息条数 | 500 | 保留最近记录，包含已记录的机器人气泡 |
| 群聊最低上下文 | 开启，50 条 | 只统计当前实际保留记录，门槛须为 1 至保留上限，私聊不限制 |
| 新增用户消息后触发摘要 | 100 条 | 只按新入站消息计算，机器人气泡不增加此计数 |
| 单次摘要最多读取消息条数 | 200 | 必须满足“触发条数 ≤ 摘要窗口 ≤ 保留条数” |
| 消息正文上下文字符预算 | 16000 | 限制观察资料的大小 |
| 日记上下文字符预算 | 2400 | Recorder 与主模型读取近期日记时使用，选择完整话题 |
| 单次日记变更输出字符上限 | 6000 | 限制一次总结输出，不限制每日累计日记 |
| 摘要模型超时 | 60 秒 | 超时或输出错误时保留进度，后台后续重试 |

日记按会话、日期和话题保存，允许补充或更正当天话题，历史日期封存。聊天记录滚动删除，日记持续保留至管理员清理。图片／视频／文件在插件记录中使用 `[image]`、`[video]`、`[file]` 等标签；媒体理解由宿主处理。

新收到的戳一戳通知会记录发起者、目标 QQ 及目标是否为本机器人，模型观察中也包含这些信息；不会自动作为 @ 必回复，新增事件描述也不参与昵称匹配。目标缺失时标为未知。旧 `[poke]` 记录不回填、不迁移。

“过滤群机器人消息”仅在 Recorder 启用且选中的群生效：确认是机器人后，新消息不入库、不增加计数、不触发默认回复或 Humanization 调度；私聊不受影响。原生群消息存档及其他插件指令仍保留。开启后，即使 Controller 关闭，也过滤此类入站消息及其默认回复。

接管的主模型使用插件已过滤的观察资料替代原生群聊上下文文本块，避免昵称混排的文本块带回机器人消息；这会失去该原生文本块独有的额外消息／图片描述。带发送者 ID 的原生机器人回合及其回复只在推理时排除，保存前恢复；当前可识别的机器人引用在媒体提取前排除。旧插件原始消息在读取时同样筛选，但不删除旧数据或改写既有日记。无发送者身份的旧原生回合、已压缩摘要以及工具主动查询的结果不作猜测性过滤。

识别通过已有适配器查询群成员信息，不调用 LLM；确认结果缓存 10 分钟，未知／失败缓存 30 秒，单次请求超时 3 秒。普通 QQ 账号运行的第三方机器人未必带此标识。保存配置并重载插件后生效。

最低上下文沿用 Recorder 的指令过滤和去重，滚动删除的消息不计数。观察期间仍记录、整理日记，群聊中的 @／提及必回复和主动发言也受门槛限制；重置群聊数据后重新积累。

### Controller：频率与回复规划

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 工作模式 | 消息调度 | 累加积极度安排评估；可切换概率抽样 |
| 机器人名称／别名 | `Bot`／空 | 用于点名识别和 Controller 身份提示，需另行同步到主人格 |
| 群聊／私聊积极度 | 0.2／0.8 | 控制评估频率，范围 0—1 |
| @ 必回复／提及必回复 | 开启／关闭 | 绕过普通频率门控和冷却，仍规划情绪与表达 |
| 名称提及／@ 积极度下限 | 0.3／1.0 | 未启用对应必回复时，提高该消息的评估频率 |
| 时区 | `Asia/Shanghai` | 用于时段、日记和日志时间 |
| 普通回复冷却／合并等待 | 20 秒／1.5 秒 | 控制连续发言并合并相邻消息 |
| 调度最短／最长补偿等待 | 5 秒／60 秒 | 低流量时也提供评估机会，仅调度模式显示 |
| Controller 和主模型观察消息条数 | 30 | 与群聊最低上下文门槛独立 |
| Controller 读取话题数／字符预算 | 30／12000 | 跨日期选择最近更新的话题，条数为 0 时不读取 |
| 门控／格式修复超时 | 30 秒 | 普通规划失败保持安静，必回复保留主模型入口 |
| 代理回合禁用工具 | 空 | 从宿主允许的工具中进一步移除指定工具 |

积极度是**评估机会的频率**，实际发言还由 Controller 判断。调度模式下，0.1 名义上约每 10 条消息评估一次，0.2 约每 5 条，0.5 约每 2 条，0.8 平均约每 1.25 条；低流量补偿、合并、冷却与退避会改变实际间隔。概率模式按积极度随机抽样。

积极度为 1 仍允许 Controller 决定沉默；为 0 时普通消息不评估，已开启的必回复仍有效。必回复只要求进入回复流程，角色仍可拒绝用户任务。

可配置多个群聊／私聊积极度时段，未覆盖时使用默认值。支持跨午夜；开始时间包含、结束时间不包含，相同起止表示全天，时段不能重叠。配置页只显示当前模式的专属参数；频率估计在保存重载并重新打开页面后更新。

Controller 会规划当前情绪、参与方式和回复方向，每个会话保留最近 10 条有效决策，供后续判断参考。名称和别名识别只是线索，模型仍会结合语境判断消息是否指向自己。

### 空闲主动发言

默认关闭，仅用于已整体启用的群聊。默认无人发言 60 分钟后，每 15 分钟检查一次；距机器人上次发言至少 240 分钟，每群每天最多 2 次。主动评估系数默认 0.5，23:00—08:00 默认免打扰。

主动发言仍需 Controller 判断；开启不代表必定开口。无人回应后不连续追发，新消息会使过时的主动意图失效。

### 提示词与人格

主回复人格使用 AstrBot 当前人格。插件另外提供“行为风格”“表达风格”“群聊”“私聊”四份可编辑文本，也可选择人格正文覆盖：

- 行为风格指导 Controller 是否参与及如何规划。
- 表达风格指导主模型如何说话。
- 群聊／私聊文本按场景提供给 Controller 和主模型。

Controller 不会自动读取主人格，角色的重要兴趣、边界和倾向也应写入行为风格。选择人格覆盖后，以该人格正文为准；未选择人格且文本留空时读取内置默认 TXT，不把默认正文写回配置。

最终聊天正文采用单行纯文本，可用半角 `$` 分成 1—3 个气泡。大多数回复只用文字，少数回复允许在最后一个气泡的文字末尾加一个 emoji。格式错误时最多修复一次。固定 JSON 与输出协议由插件维护，风格文本应与其一致。

### 日志设置

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 日志等级 | INFO | DEBUG、INFO、WARNING、ERROR、CRITICAL，包含更高等级 |
| 文件大小上限 | 10 MB | 统一 humanization.log，保留 3 份轮转备份，0 不限 |
| 调试模式 | 关闭 | 展开二级选项并解锁 TRACK，不自动提高详细程度 |
| 数据脱敏 | 关闭 | 遮盖 UMO 会话号、发言人及聊天文字的中间部分 |
| 日志回显 | 关闭 | 同时送到 AstrBot 控制台，仍受宿主等级过滤 |

TRACK 逐函数追踪插件调用者、目标、结果摘要和耗时，开销高于普通日志，建议临时排障使用。关闭调试模式后，TRACK 自动回到 INFO；脱敏和回显各自按保存值独立生效。TRACK 回显为 DEBUG 并带有 [TRACK] 标记。

文件沿用 AstrBot 的时间、插件名、级别及代码位置格式。INFO 记录 Controller／Recorder 开始与结果、回复流程和管理操作；辅助模型用量并入结果，主模型可观察步骤单独记录。异常保留必要堆栈，聊天和模型内容只在 DEBUG 中以有界摘要呈现，凭据与二进制始终过滤。脱敏保留首尾信息，不等于匿名化。

新版本不再写入 dev.log 和 runtime.log，旧文件不会自动删除。保存重载后生效；正常关闭会排空日志，但断电或强制结束进程不能保证最后一条落盘。

## 管理指令

在设置中开启“管理指令”（默认关闭），并将宿主唤醒前缀配置为包含 `/`。若同时使用空前缀，将 `/` 排在空前缀之前。配置 `/` 后仍能监听普通聊天。

所有 `/hum` 指令仅 AstrBot 管理员可用，普通用户使用时不回应。`[UMO]` 是可选参数，省略表示当前会话，指定目标的重置命令只允许在管理员私聊中使用。

| 指令 | 位置 | 功能 |
| --- | --- | --- |
| `/hum info [UMO]` | 群聊／私聊 | 查询会话名称、UMO、记录条数、日记版本与进度、辅助模型及查询时间 |
| `/hum clear log` | 私聊 | 清空活动 `humanization.log`，保留备份并记录清理结果；也接受 `/hum claer log` |
| `/hum reset_data all [UMO]` | 当前会话，或私聊指定目标 | 清空全部聊天、日记、规划记录与进度，主模型切换空白对话 |
| `/hum reset_data today [UMO]` | 同上 | 清空全部聊天和规划记录，只删请求当天日记，保留此前日记 |

重置需同一管理员在发起请求的同一会话内，于 60 秒内输入 `/hum IClearKnowWhatIDoingNow` 确认，超时不执行。群聊重置作用于整群，主模型旧对话保留供查看；此前日记在 `today` 重置后仍可被读取。

例如，在管理员私聊中发送 `/hum reset_data all onebot:GroupMessage:123456`，再在该私聊确认，即重置目标群。

管理页面设置标签最下方的红色“危险操作区”可清除所有已记录会话的数据。点击“清除所有会话数据”，在弹窗中完整输入 `CLEAR_ALL_HUMANIZATION_DATA`，再点击“确认清除”即立即执行；同时为对应主模型新建空白对话，保留原生旧对话和日志文件。此操作不保存配置，也不需要重载插件；原生插件配置中不再设置清除开关。

## 数据与常见问题

数据保存在 AstrBot 插件数据目录：数据库为 `chat/db/chat.sqlite3`，日志为 `log/humanization.log`（轮转备份为 .1～.3）。日志与数据库不要提交 Git；调试日志包含聊天与模型内容，分享前先检查。

- **没有回复？** 检查会话范围、模块开关、宿主 LLM 开关、规划模型及群聊最低上下文，再看插件 humanization.log 的规划日志（开启回显后也可在 AstrBot 查看）。评估通过也可能决定沉默。
- **没有日记？** 需要选择摘要模型并积累足够新增用户消息，整理在后台进行，不阻断聊天回复。
- **指令为什么还在原生记录中？** 过滤控制插件记录和 LLM 输入，原生记录保留；已有日记不会因修改过滤设置而重写。
- **数据库旁有 WAL／SHM？** 它们由 SQLite 管理，正常运行时存在是正常现象；插件关闭时会尝试整理，外部读连接可能阻止完成，不要直接删除。
- **配置了名称，主模型仍不认识外号？** 名称／别名只自动注入 Controller，需要同步到 AstrBot 主人格。

开发结构、协议、算法、数据库及验证方式见 [开发说明](docs/DEV.md)；各版本变化见 [CHANGELOG](CHANGELOG.md)。
